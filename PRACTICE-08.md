## Точна локальна політика

Один процес, один worker, БЕЗ reload і reverse proxy. ЄДИНИЙ загальний
ліміт на POST /api/v1/auth/login. Типово N=5 допущених звернень за T=60 с.
Перше допущене звернення починає [start,start+T). На now>=start+T починається
нове вікно. Перші N дозволені; решта 429. Відхилення не збільшує лічильника
і не подовжує вікно. Retry-After=ceil(залишку), щонайменше 1 секунда.

Рахуються ВСІ відповідні POST до читання тіла й перевірки пароля: правильні,
помилкові та некоректний JSON. Успішний вхід не скидає лічильник. Інші
маршрути, методи й /health не витрачають квоти. Вхідні X-Forwarded-For,
Forwarded, X-Request-ID та зміна логіна не створюють нову квоту.

Це глобальний вхідний ліміт навчального стенда, НЕ повний захист облікового
запису від розподіленого добору. Усі локальні користувачі ділять квоту,
перезапуск очищує її, на межі вікон можливий сплеск. Пам'ять постійна:
жодного словника довільних логінів/IP. Статус user, зокрема blocked, не змінюється.
Для виробничої системи потрібна окрема політика кількох шарів і спільний стан.

Довірена конфігурація середовища: `DEAN_LOGIN_MAX_ATTEMPTS` від 1 до 1000 та
`DEAN_LOGIN_WINDOW_SECONDS` від 1 до 3600.
Некоректні типи/діапазони — відмова запуску. Це межі навчальної конфігурації,
не універсальна рекомендація. Немає HTTP-зміни політики чи скидання стану.

## Що реалізувати

1. limiter.FixedWindowLimiter.admit: критична секція, монотонний годинник,
   точна межа, округлення та атомарне рішення паралельних викликів.
2. events.register_limit_event: ідемпотентне доповнення каталогу №7
   auth.login_limited=WARNING без послаблення Event/форматувальника.
3. middleware.LoginThrottleMiddleware: ASGI-фільтр ДО router/dependencies,
   БЕЗ читання тіла для 429; дозволений запит передається без зміни повідомлень.
4. integration.install_practice08: інтеграція після install_practice07(app)
   у власному app/main.py; один limiter у state, збережені lifespan/маршрути.
5. Власний безпечний resolver маршруту №7: якщо
   scope.get('practice08_route_template') точно дорівнює LOGIN_PATH,
   використайте цю серверну константу; інакше наявний шаблон або <unmatched>.
6. Версія 0.8.0 у застосунку та pyproject.toml, 429 у наявному OpenAPI входу;
   тести, порівняльний дослід, мініаудит, схема й план удосконалень.

## Порядок і контракт

P7 SecurityLogMiddleware → P8 LoginThrottleMiddleware → маршрутизатор №6.
У списку app.user_middleware P8 вставляється ОДРАЗУ ПІСЛЯ P7, не через
звичайний add_middleware, який розмістив би його зовні. Контекст №7 мусить
існувати і для 429. Provider бере один поточний limiter з app.state.
Повторна або запізніла інсталяція має відмовляти до побічних ефектів.

429: JSON {"detail":"too many login attempts"}, Retry-After додатне ціле
десяткове число секунд, Cache-Control:no-store, серверний X-Request-ID.
Немає токена, WWW-Authenticate або виконання перевірки пароля/SQL.
Подія auth.login_limited: WARNING, outcome=denied, action=login.limit,
method=POST, route=/api/v1/auth/login, status429, actor/role/session_ref=null.
Не створюйте auth.login_failed/token_issued для спроби, яку не автентифікували.
Зовнішній №7 створює ОДНУ http.completed; обидві події мають UUID відповіді.
Збій файлового запису не відкриває доступ і не змінює 429 на успіх.

Немає нових бізнес/службових/reset/audit HTTP-методів. Набір №7 зберігається:
20 бізнес-операцій плюсhealth. Старі незахищені та криптографічні лабораторні
router залишаються непідключеними. Їхні модулі переглядають локально.

## Перевірки та експеримент

```bash
python -m pytest tests/test_practice08_limiter.py tests/test_practice08_api.py
python -m uvicorn app.main:app --host 127.0.0.1 --workers 1 \
  --no-access-log --no-proxy-headers
```

Конфігурацію JWT №6 і журналу №7 збережіть. Для регресій №6–7 фікстури
отримують окремий новий limiter із вищою допустимою тестовою квотою;
перевірку версії узгодьте з 0.8.0. Не видаляйте старих безпекових тверджень,
не вимикайте JWT/RBAC/аудит і не додавайте production bypass заради тестів.
Окремі №8 сценарії завжди перевіряють малу квоту й її реальні відмови.

Вісім синтетичних звернень у тому самому моменті керованого часу:
порахуйте допуск, відмови та виклики контрольного дорогого кроку до/після
зміни. У базовій лінії контрольний callback викликається для кожного звернення;
після зміни лише за Decision.allowed. Це ізольована модель вартості, не
вимірювання швидкості PBKDF2 і не масовий добір реальних паролів.

## Postman

Колекція digital-dean-practice-08.postman_collection.json містить 10 запитів.
Запускайте одразу після чистого перезапуску процесу з типовим N5/T60 та
чинним синтетичним lab_teacher_a. lab_password установіть лише локально.
Серія має завершитися протягом 60 с; колекція припиняє несумісний запуск.
Не робіть інших звернень входу під час сценарію. Відновлення після вікна
перевіряється pytest з керованим часом; додатково можна вручну повторити
вхід після фактичного Retry-After. Клієнтський токен наприкінці очищується,
що не є його серверним відкликанням. Не експортуйте пароля або токенів.
