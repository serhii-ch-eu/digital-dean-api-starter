# Звіт з практичної роботи 8

## 1 Мета та межі
Власний форк, гілка, базовий і фінальний теги, версії Python і залежностей.
Тільки локальний стенд та синтетичні записи. Точна політика N/T і один процес.

## 2 Власні зміни API
Алгоритм, критична секція, порядок middleware, каталог подій, OpenAPI.
Власні фрагменти коду та посилання на змістові коміти після practice-08-base.

## 3 Відтворюваний експеримент
За однакового сценарію порівняйте 8 синтетичних звернень у межах одного
вікна: допущено, відхилено, викликів контрольного дорогого кроку.
Вкажіть результат до зміни, після зміни й момент відновлення доступності.
Не вигадуйте часових вимірювань і не називайте швидкість повернення 429
прискоренням обчислення парольного хешу. Не запускайте масовий добір.

## 4 Перевірки та докази
Команди pytest, результати, контроль часу, паралельність; очищена колекція.
UUID відповіді та мінімальний синтетичний JSONL-витяг для 429; відсутність
пароля/логіна/токена. Історія оцінок збережена, відхилений вхід її не змінює.
Неперевірені пункти позначте як неперевірені, а не успішні.

## 6 Цільова архітектура та план удосконалення
Схема фактичного застосунку з місцем нового контролю; SQLite, grade_audit,
JSONL, конфігурація секретів. Окремо позначте НЕреалізовані компоненти
виробничого контуру: захищений транспорт, спільний ліміт кількох процесів,
багатофакторна автентифікація, незалежне зберігання журналів та резервування.
Щонайменше три вдосконалення з відповідальним, пріоритетом і критерієм приймання.

## 7 Історія та висновок
Щонайменше 5 власних змістових комітів, фінальний тег, межі доказів.
Не називайте локальний мініаудит сертифікацією або повним тестом на проникнення.

## 8 Алфавітний глосарій термінів та абревіатур
Останній розділ. Для використаних абревіатур подайте повну назву й пояснення
українською. Виноски не використовуються.
